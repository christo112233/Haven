# Haven 开发文档

本文面向需要修改、测试或发布 Haven 的开发者。安装和日常使用方法见 [README](../README.md)。以下内容以当前源码为准；版本号以 `config.py` 和 `version.txt` 为准。

## 环境与启动

- Windows 10/11 x64、Python 3.14、Microsoft Edge WebView2 Runtime。
- `requirements.txt` 固定运行和构建依赖；Node.js 与 Playwright 只用于可选的前端验证，不进入发布包。
- 建议在仓库根目录使用 `venv/`，命令不依赖激活虚拟环境。

```powershell
python -m venv venv
venv\Scripts\python.exe -m pip install -r requirements.txt
venv\Scripts\python.exe main.py
```

指定初始目录或在浏览器中调试：

```powershell
venv\Scripts\python.exe main.py --folder "D:\Photos"
venv\Scripts\python.exe main.py --browser --port 8765
```

浏览器模式会在终端打印带会话令牌的完整本地地址；服务只监听 `127.0.0.1`。桌面模式使用 pywebview 的 EdgeChromium/WebView2 窗口。两种模式共用前端、HTTP 媒体服务和 `Api` 业务对象；浏览器模式通过 `/api/...` 调用业务方法，桌面模式优先使用 `window.pywebview.api`。浏览器模式没有原生文件夹选择器，可在界面中输入路径。

## 代码结构

| 文件 | 职责 |
| --- | --- |
| `main.py` | 参数解析、启动服务与原生窗口、注册桥接方法、原生文件夹拖放、启动后的更新检查及资源关闭。 |
| `config.py` | 版本、资源与数据路径、支持格式、扫描忽略规则、更新仓库地址。 |
| `api.py` | 文件夹、扫描任务、分页与筛选、文件操作、元数据、智能相册、设置和更新的业务接口。 |
| `server.py` | 静态资源、令牌保护的 JSON API、媒体输出和视频 Range 请求；`METHODS` 是 HTTP 与原生桥接共同的接口白名单。 |
| `scanner.py` | 使用 `os.scandir()` 枚举媒体和子文件夹、搜索目录、识别 Live Photo 配对、复用目录索引。 |
| `cache.py`、`thumbs.py` | `.Haven` 缓存的所有权与原子写入、缩略图和大图预览的生成及失效判断。 |
| `metadata.py`、`raw_handler.py`、`heic_handler.py`、`video_handler.py` | EXIF、RAW、HEIC 与视频的读取和解码适配。 |
| `metadata_store.py` | SQLite 中的评分、状态、标签、颜色标签及智能相册；不写入原始媒体文件。 |
| `web/index.html`、`web/app.js`、`web/style.css` | 页面结构、交互状态与布局样式。没有前端框架或打包步骤。 |
| `web/liquid-glass.js`、`web/shaders/` | 共享 WebGL2 玻璃渲染、指针效果、主题过渡及 CSS 回退。 |
| `updater.py`、`updater_src/updater.py` | 主程序的清单检查、下载与交接；独立更新器的替换、回滚及重启。 |
| `build.spec`、`scripts/build.ps1`、`scripts/release_manifest.py` | PyInstaller 打包、独立更新器构建、ZIP 和更新清单生成。 |

## 运行时数据流

1. `main.py` 创建 `Api`，启动 `server.py`，再打开桌面窗口或输出浏览器地址。`Api.bootstrap()` 向前端返回设置、版本和运行模式。
2. 前端 `openFolder()` 调用 `Api.open_folder()`。后端创建新的扫描任务并取消旧任务；`Api._scan()` 在后台执行 `scanner.scan()`，从未变化文件的 `.Haven/index.json` 复用结果，再补齐元数据与缩略图。
3. 普通文件夹扫描中的常规影像处理使用线程池，RAW 使用进程池。任务记录 `scanning`、`processing`、`ready` 或 `error` 状态、进度和修订号。前端轮询任务，并通过 `page()` 按文件名、类型、元数据条件和排序获取结果；单次最多返回 200 项。
4. `web/app.js` 的 `visibleGrid()` 根据容器宽度、滚动位置和缩略图尺寸计算可见行；`renderGrid()` 只保留视口上方 2 行、下方 3 行内的卡片，照片数据按 200 项分页。滚动到新范围、改变尺寸或筛选条件时重新计算；异步分页完成后再次核对当前范围，避免快速滚动显示旧位置。
5. 卡片和查看器通过 `/media?mode=thumb|preview|original` 获取图像。视频和 Motion Photo 也由本地 HTTP 服务输出，视频支持 Range 请求。前端仅在需要显示时请求图像。

路径访问由 `Api.authorize()` 限制在已添加的根目录内；媒体接口还会核验文件类型。`server.py` 校验请求 Host 和启动时生成的令牌，静态文件路径也限制在 `web/` 下。新增业务接口时，需要同时实现 `Api` 方法并加入 `server.METHODS`，再决定前端如何调用；不要直接暴露窗口对象或任意文件路径。

`web/app.js` 的 `api(method, ...args)` 用同一组位置参数调用桌面桥接或浏览器 HTTP API。浏览器请求为 `POST /api/<method>`，JSON 请求体是参数数组，响应为 `{ "result": ... }` 或 `{ "error": "..." }`；媒体请求走独立的 `GET /media`。例如 `fetchPage()` 传入任务 ID、偏移量、页大小、搜索词、类型、排序方向和元数据筛选条件。修改方法签名时，应核对两个调用通道及对应测试。

## 文件夹、元数据与界面状态

目录树通过 `Api.folders()` 按需获取直属子目录与媒体数量。侧边栏搜索调用 `Api.search_folders()`，在所有已添加根目录下仅遍历目录名，最多返回 100 项；点选结果后前端展开祖先节点并打开目标目录。照片区顶部的子文件夹栏使用同一 `folders()` 接口，独立于当前照片搜索和筛选。创建、重命名或移动文件后，前端会失效相关目录缓存并刷新视图。

`metadata_store.py` 使用 SQLite WAL 模式保存照片评分、收藏、旗帜、Rejected、颜色标签、普通标签和智能相册定义。扫描时按文件系统标识或路径核对记录；重命名、移动和删除路径时由业务层同步数据库。照片目录中的 `.Haven` 仅保存扫描索引与派生图像，和用户标注数据库是两套数据。智能相册在已添加根目录中递归扫描，按条件的 `and` / `or` 逻辑匹配；条件目前包含标签、评分、颜色标签和三个布尔状态。

前端交互集中在 `web/app.js`。`state.epoch` 用于忽略切换文件夹后的过期扫描或分页响应，子文件夹和目录搜索另有请求序号。选择模式、批量操作、查看器、智能相册和玻璃样式下拉框由该文件维护。侧边栏宽度是前端 `localStorage` 项 `haven.sidebar-width`，会按窗口大小限制显示；它不在后端设置文件中。修改照片元数据后，前端更新已加载页面和当前查看器数据，再按需要重跑筛选或智能相册。

液态玻璃使用共享 WebGL2 画布绘制背景折射与交互效果，弹窗有独立画布；`web/style.css` 提供无 WebGL2 时的磨砂玻璃样式。改动动态创建的玻璃控件时，检查 `web/liquid-glass.js` 的表面选择与刷新逻辑，避免只改 CSS 后失去指针融合效果。

### 扩展入口

- 新增媒体格式：先在 `config.py` 对应集合中登记扩展名，再检查 `scanner.py` 的分类、`metadata.py` 和 `thumbs.py` 的处理路径，以及 `server.py` 的原图响应是否适用；用真实样本补充格式测试。
- 新增照片标注或智能相册条件：在 `metadata_store.py` 定义存储与校验，在 `Api._matches_filters()` / `_condition_filter()` 加入匹配规则，再更新前端编辑、筛选、批量操作和查看器同步逻辑。现有 SQLite 表使用 `CREATE TABLE IF NOT EXISTS`，修改列结构时需要显式迁移旧数据库。
- 新增界面交互：在 `web/index.html` 放置结构，在 `web/app.js` 绑定行为，在 `web/style.css` 处理宽窄窗口和深浅主题；新增玻璃表面时检查 `web/liquid-glass.js` 的采样与指针合成，并验证键盘操作。

## 数据与缓存位置

| 位置 | 内容 |
| --- | --- |
| 程序目录 `haven-settings.json` | 根目录、展开状态、当前目录、外观、缩略图大小、更新偏好等设置。 |
| 程序目录 `haven-metadata.sqlite3` | 用户标注和智能相册；SQLite 运行时还可能生成 `-wal`、`-shm` 文件。 |
| 程序目录 `.haven-runtime/` | WebView2 用户数据与前端本地存储。 |
| 照片目录 `.Haven/index.json` | 扫描索引；文件修改时间、大小和缓存版本决定能否复用。 |
| 照片目录 `.Haven/thumbs/`、`.Haven/previews/` | 最长边分别为 512px 的 WebP 缩略图、2560px 的 JPEG 预览及其签名文件。 |
| 照片目录 `.Haven/owner.json` | 缓存所有权标记，清理时拒绝删除非 Haven 创建的同名目录。 |
| 程序目录 `.updates/` | 更新下载与替换工作目录；成功更新后清理，失败资料保留以便恢复。 |

只读照片目录可用内存中的预览继续浏览，但缓存无法持久写入。移除根目录不会清除照片或 `.Haven`；清理缓存走所有权检查。程序目录需要可写，否则设置、元数据库、WebView2 资料和更新可能无法正常保存。

## 验证

后端测试覆盖缓存与只读目录、目录搜索、元数据和智能相册、重命名/移动、格式处理、API 访问限制及更新回滚。真实 RAW 测试需要可选样本 `.qa/sample.CR2`，缺少时会跳过。

```powershell
venv\Scripts\python.exe -m unittest discover -s tests -v
venv\Scripts\python.exe scripts\native_smoke.py
```

需要检查 UI 时可启动独立预览服务，`--folder` 指向测试照片目录；它会打印访问地址，并将界面设置写入 `.qa/preview-ui-settings.json`：

```powershell
venv\Scripts\python.exe scripts\preview_ui.py --folder "D:\TestPhotos"
```

注意：预览脚本只隔离设置文件，默认仍使用程序目录的 `haven-metadata.sqlite3`。测试评分、标签或智能相册时应使用独立工作副本或专门的测试数据。`scripts/verify_ui.cjs`、`verify_glass.cjs` 及其他 `verify_*.cjs` 使用 Playwright；先在 `.qa/` 安装 Playwright 和 Chromium。`verify_ui.cjs` 还要求 `.qa/gallery/` 中有命名为 `Photo-000.jpg` 至 `Photo-244.jpg` 的 245 张测试照片，以及可访问的服务 URL（`HAVEN_URL` 或 `.qa/server.log`）。这些脚本不属于发布程序的依赖。

改动扫描、元数据或文件操作时运行后端测试；改动布局、玻璃效果、目录树、虚拟网格或查看器时，再用相应的浏览器脚本和原生窗口检查。浏览器预览不能代替 WebView2 的文件夹选择、原生拖放与窗口操作验证。

## 构建与发布

`build.spec` 将主程序打包为 `dist/Haven/` 的 one-folder 目录；`scripts/build.ps1` 另行构建 one-file 的 `updater.exe`，然后生成 `dist/Haven-win64.zip` 和 `dist/update.json`。ZIP 根目录直接包含 `Haven.exe`、`updater.exe`、`version.txt` 与 `_internal/`，不能再包一层目录。构建前关闭正在使用 `dist/Haven/` 的程序。

```powershell
venv\Scripts\python.exe -m unittest discover -s tests -v
powershell -ExecutionPolicy Bypass -File scripts\build.ps1
```

发布时同时更新 `config.py` 的 `VERSION` 和 `version.txt`。`scripts/release_manifest.py` 会检查两者一致，按独立更新器的 `OWNED` 列表打 ZIP，并生成下载地址、字节大小和 SHA256。标签格式为 `vX.Y.Z`；清单必须与同一次构建的 ZIP 一起发布。GitHub Actions 的 `Windows Release` 工作流在推送版本标签时运行测试、构建并发布 Release；手动触发只上传构建产物。自动更新从正式 Latest Release 的 `update.json` 读取清单。

主程序只接受更高版本、指定仓库的 HTTPS 下载地址以及合法的大小和 SHA256。用户确认后，`updater.py` 把更新包与独立更新器放入 `.updates/` 并退出主程序；独立更新器再次校验 ZIP、备份可替换的程序文件、安装新版本，失败时尝试回滚。用户设置、SQLite 数据库和照片目录不在替换列表中。新版本启动后会清理已完成更新的旧备份；失败目录和错误记录保留。源码运行可检查更新，但完整自动替换流程需要打包版验证。

发布前还应在干净的 Windows 环境检查 WebView2、真实 RAW/HEIC、视频、回收站和一次从旧版到新版的升级，并确认 [第三方许可声明](../THIRD_PARTY_NOTICES.md)随包分发。
