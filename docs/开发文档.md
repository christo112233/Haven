# Haven 开发文档

本文面向需要修改、测试或发布 Haven 的开发者。安装和日常使用方法见 [README](../README.md)。以下内容以当前源码为准；版本号以 `config.py` 和 `version.txt` 为准。Windows 与 macOS 共用同一份代码、同一个版本号，发布时由 CI 同时构建。

## 环境与启动

- **Windows**：Windows 10/11 x64、Python 3.14、Microsoft Edge WebView2 Runtime。
- **macOS**：macOS 11+（Apple Silicon）、Python 3.14；PyInstaller 打包需要 Xcode Command Line Tools。macOS 使用 pywebview 的 Cocoa 后端（WKWebView），不需要 WebView2。
- `requirements.txt` 固定运行和构建依赖；Node.js 与 Playwright 只用于可选的前端验证，不进入发布包。
- Windows 建议在仓库根目录使用 `venv/`，macOS 建议 `.venv/`，命令不依赖激活虚拟环境。
- `HAVEN_DATA_DIR` 环境变量可以覆盖用户数据目录，用于便携运行、测试和沙箱环境。

```powershell
# Windows
python -m venv venv
venv\Scripts\python.exe -m pip install -r requirements.txt
venv\Scripts\python.exe main.py
```

```bash
# macOS
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python main.py
```

指定初始目录或在浏览器中调试：

```bash
python main.py --folder "D:\Photos"
python main.py --browser --port 8765
```

浏览器模式会在终端打印带会话令牌的完整本地地址；服务只监听 `127.0.0.1`。桌面模式在 Windows 使用 EdgeChromium/WebView2，在 macOS 使用 Cocoa/WKWebView。两种模式共用前端、HTTP 媒体服务和 `Api` 业务对象；浏览器模式通过 `/api/...` 调用业务方法，桌面模式优先使用 `window.pywebview.api`。浏览器模式没有原生文件夹选择器，可在界面中输入路径。

## 代码结构

| 文件 | 职责 |
| --- | --- |
| `main.py` | 参数解析、启动服务与原生窗口、平台分支（WebView2/Cocoa、图标、数据目录）、注册桥接方法、原生文件夹拖放、启动后的更新检查及资源关闭。 |
| `config.py` | 版本、资源/数据目录、支持格式、扫描忽略规则、更新仓库地址。 |
| `macos_menu.py` | macOS 原生菜单栏（AppKit NSMenu）：快捷键、勾选状态、动态启用，通过 `haven:menu` 事件驱动前端。 |
| `platform_support.py` | 平台适配层：打开/显示文件、剪贴板文件复制、编辑器检测、文件名校验、路径比较、子进程参数、macOS 原生窗口与 zoom。 |
| `api.py` | 文件夹、扫描任务、分页与筛选、文件操作、元数据、图库位置、智能相册、设置和更新的业务接口。 |
| `server.py` | 静态资源、令牌保护的 JSON API、媒体输出和视频 Range 请求；`METHODS` 是 HTTP 与原生桥接共同的接口白名单。 |
| `scanner.py` | 使用 `os.scandir()` 枚举媒体和子文件夹、搜索目录、识别 Live Photo 配对、复用目录索引。 |
| `cache.py`、`thumbs.py` | `.Haven` 缓存的所有权与原子写入、平台中立的缓存签名、缩略图和大图预览的生成及失效判断。 |
| `library.py` | 共享图库身份：根目录标记、相对路径 + Unicode NFC 归一化、图库目录/数据库/备份、旧库拷贝。 |
| `metadata.py`、`raw_handler.py`、`heic_handler.py`、`video_handler.py` | EXIF、RAW、HEIC 与视频的读取和解码适配。 |
| `metadata_store.py` | 按 `root_id + 相对路径` 保存评分、状态、标签、颜色标签及智能相册；兼容旧版本地数据库迁移；共享库使用网络盘安全设置。 |
| `web/index.html`、`web/app.js`、`web/style.css` | 页面结构、交互状态与布局样式。没有前端框架或打包步骤；按 `bootstrap.platform` 适配文案与窗口行为。 |
| `updater.py`、`updater_src/updater.py`、`updater_macos.py` | 清单检查与按平台选择产物；Windows 用独立 `updater.exe` 替换；macOS 下载校验后由临时 shell 助手等待进程退出、备份并替换 `.app`，失败自动回滚，首次成功启动后清理旧版本。 |
| `build.spec`、`build-mac.spec`、`scripts/build.ps1`、`scripts/build_macos.sh`、`scripts/release_manifest.py` | 双平台 PyInstaller 打包、独立更新器构建、ZIP/DMG 与多平台更新清单生成。 |

## 运行时数据流

1. `main.py` 创建 `Api`，启动 `server.py`，再打开桌面窗口或输出浏览器地址。`Api.bootstrap()` 向前端返回设置、版本、运行模式、平台和当前图库信息。
2. 前端 `openFolder()` 调用 `Api.open_folder()`。后端创建新的扫描任务并取消旧任务；`Api._scan()` 在后台执行 `scanner.scan()`，从未变化文件的 `.Haven/index.json` 复用结果，再补齐元数据与缩略图。
3. 普通文件夹扫描中的常规影像处理使用线程池，RAW 使用进程池。任务记录 `scanning`、`processing`、`ready` 或 `error` 状态、进度和修订号。前端轮询任务，并通过 `page()` 按文件名、类型、元数据条件和排序获取结果；单次最多返回 200 项。
4. `web/app.js` 的 `visibleGrid()` 根据容器宽度、滚动位置和缩略图尺寸计算可见行；`renderGrid()` 只保留视口上方 2 行、下方 3 行内的卡片，照片数据按 200 项分页。滚动到新范围、改变尺寸或筛选条件时重新计算；异步分页完成后再次核对当前范围，避免快速滚动显示旧位置。
5. 卡片和查看器通过 `/media?mode=thumb|preview|original` 获取图像。视频和 Motion Photo 也由本地 HTTP 服务输出，视频支持 Range 请求。前端仅在需要显示时请求图像。

路径访问由 `Api.authorize()` 限制在已添加的根目录内；媒体接口还会核验文件类型。`server.py` 校验请求 Host 和启动时生成的令牌，静态文件路径也限制在 `web/` 下。新增业务接口时，需要同时实现 `Api` 方法并加入 `server.METHODS`，再决定前端如何调用；不要直接暴露窗口对象或任意文件路径。

`web/app.js` 的 `api(method, ...args)` 用同一组位置参数调用桌面桥接或浏览器 HTTP API。浏览器请求为 `POST /api/<method>`，JSON 请求体是参数数组，响应为 `{ "result": ... }` 或 `{ "error": "..." }`；媒体请求走独立的 `GET /media`。修改方法签名时，应核对两个调用通道及对应测试。

## 共享图库与跨平台身份

用户标注不再绑定操作系统绝对路径。每张照片的稳定身份是 `root_id + 相对根目录的 POSIX 路径`：

- 添加根目录时在 `<root>/.Haven/library.json` 写入 `library_id`、`root_id` 和名称；Windows 的 `Z:\Photos` 与 macOS 的 `/Volumes/Photos` 读取同一个 `root_id`。
- 路径做 Unicode NFC 归一化，并在解析时先 `resolve()` 两侧，兼容 macOS `/var`→`/private/var` 一类的挂载前缀差异；因此 NAS 上同一份照片在两个平台得到同一身份。
- 图库数据库、`library.json` 和 `backups/` 位于「图库数据位置」：Windows 默认 `程序目录/library/`，macOS 默认 `~/Library/Application Support/Haven/library/`，也可以在 **设置 → 图库数据位置** 选择 NAS 上的共享目录。
- 共享位置会自动使用 `journal_mode=DELETE`（网络盘上不安全的 WAL 关闭）、`.lock` 单写者文件锁、`busy_timeout`，并在启动时按天生成数据库快照。
- 旧版本的 `haven-metadata.sqlite3` 首次打开时会自动迁移：按当前根目录把绝对路径改写为 `(root_id, rel_path)`，无法匹配的记录保留在 `legacy_unmatched` 表。
- 图库目录不可用时仍可浏览照片和使用 `.Haven` 缓存，但标注不可用；设置界面会显示警告。
- 根目录本身被重命名时，标注不需要搬动（`root_id` 跟着目录里的标记文件走）；目录内的重命名/移动只更新相对路径。

照片目录中的 `.Haven` 只保存扫描索引和派生图像，和标注数据库是两套数据，可跨平台共享并在丢失后重建。

## 文件夹、元数据与界面状态

目录树通过 `Api.folders()` 按需获取直属子目录与媒体数量。侧边栏搜索调用 `Api.search_folders()`，在所有已添加根目录下仅遍历目录名，最多返回 100 项；点选结果后前端展开祖先节点并打开目标目录。照片区顶部的子文件夹栏使用同一 `folders()` 接口，独立于当前照片搜索和筛选。创建、重命名或移动文件后，前端会失效相关目录缓存并刷新视图。

`metadata_store.py` 本地图库使用 WAL，共享图库使用 DELETE journal；扫描时按 portable identity 核对记录，重命名、移动、删除和导出移动由业务层换算成新身份。旧的 SQLite 表通过 `PRAGMA user_version` 与列检测迁移，新增列时应显式迁移。智能相册在已添加根目录中递归扫描，按条件的 `and` / `or` 逻辑匹配；条件目前包含标签、评分、颜色标签和三个布尔状态；智能相册定义随图库数据库一并共享。

前端交互集中在 `web/app.js`。`state.epoch` 用于忽略切换文件夹后的过期扫描或分页响应，子文件夹和目录搜索另有请求序号。选择模式、批量操作、查看器、智能相册和各类下拉框由该文件维护。侧边栏宽度是前端 `localStorage` 项 `haven.sidebar-width`，会按窗口大小限制显示；它不在后端设置文件中。修改照片元数据后，前端更新已加载页面和当前查看器数据，再按需要重跑筛选或智能相册。

平台差异集中在 `bootstrap.platform`：macOS 使用标准原生标题栏与红绿灯（另有 `macos_menu.py` 提供的原生菜单栏：设置 ⌘,、添加文件夹 ⌘O、重新扫描 ⌘R、复制路径 ⌘⇧C、侧边栏 ⌥⌘S、外观与全屏），`platform_support.configure_macos_window()` 只确保标题、可移动性和按钮可见；不要事后追加 `NSWindowStyleMaskFullSizeContentView`，否则标题栏会落在 WebView 之下而无法拖动），隐藏自定义窗口按钮和 resize grip；顶部工具栏/品牌区保留 `pywebview-drag-region`，通过 `drag_window` 原生移动窗口；文案切换为"访达/废纸篓"，路径使用 `/` 分隔。Windows 保持无边框自定义窗口。`platform_support.py` 是新增平台行为的唯一入口，业务代码不要直接调用 `os.startfile`、`explorer.exe` 或剪贴板 API。

毛玻璃完全由 `web/style.css` 的 CSS `backdrop-filter` 实现：`.glass` 定义统一的磨砂表面，`#sidebar`、搜索框和 `dialog` / `.panel-dialog` 等表面直接设置模糊与饱和度，并保留 `-webkit-backdrop-filter` 前缀供 WebKit/WebView2 使用。设置中的毛玻璃透明度滑块写入 `--glass-transparency` 与 `--glass-alpha-factor`，alpha 系数会限制在约 0.3–1；深浅主题通过根元素 `data-theme` 切换。不再有 WebGL2 画布、着色器或自定义光标，弹窗打开动画使用 CSS keyframe。

### 扩展入口

- 新增媒体格式：先在 `config.py` 对应集合中登记扩展名，再检查 `scanner.py` 的分类、`metadata.py` 和 `thumbs.py` 的处理路径，以及 `server.py` 的原图响应是否适用；用真实样本补充格式测试。
- 新增照片标注或智能相册条件：在 `metadata_store.py` 定义存储与校验，在 `Api._matches_filters()` / `_condition_filter()` 加入匹配规则，再更新前端编辑、筛选、批量操作和查看器同步逻辑。修改列结构时必须同时处理旧库迁移。
- 新增平台行为：优先加到 `platform_support.py`，并保持 Windows 分支行为不变；macOS 分支使用系统命令或 pyobjc。新增命令调用时补充 `tests/test_platform.py`。
- 新增界面交互：在 `web/index.html` 放置结构，在 `web/app.js` 绑定行为，在 `web/style.css` 处理宽窄窗口和深浅主题；新增毛玻璃表面时沿用 `.glass` 或直接设置 `backdrop-filter`，并验证键盘操作。

## 数据与缓存位置

| 位置 | Windows | macOS |
| --- | --- | --- |
| 设置 `haven-settings.json` | 程序目录 | `~/Library/Application Support/Haven/` |
| 图库数据库 `library/library.sqlite3` | 程序目录（可由设置改为共享目录） | `~/Library/Application Support/Haven/library/`（可改共享目录） |
| 图库标记/备份 | 图库目录 `library.json`、`backups/` | 同左 |
| WebView 数据 | 程序目录 `.haven-runtime/` | WKWebView 默认数据目录（系统管理，不在 .app 内） |
| 照片目录 `.Haven/` | `index.json`、`thumbs/`、`previews/`、`owner.json`、`library.json` | 同左（与 Windows 共用） |
| 更新暂存 | 程序目录 `.updates/` | `~/Library/Application Support/Haven/updates/`（成功后清理） |

程序目录/用户数据目录需要可写，否则设置、图库和缓存可能无法保存。macOS 的 `.app` 是签名封包，运行时绝不写入；更新或替换 `.app` 不会影响用户数据目录。只读照片目录可用内存预览继续浏览，但缓存与根目录标记无法持久化。

## 验证

后端测试覆盖缓存与只读目录、目录搜索、共享图库身份与迁移、元数据和智能相册、重命名/移动、平台适配、格式处理、API 访问限制及更新回滚。真实 RAW 测试需要可选样本 `.qa/sample.CR2`，缺少时会跳过。

```powershell
# Windows
venv\Scripts\python.exe -m unittest discover -s tests -v
venv\Scripts\python.exe scripts\native_smoke.py
```

```bash
# macOS
.venv/bin/python -m unittest discover -s tests -v
.venv/bin/python -m py_compile platform_support.py library.py metadata_store.py
```

macOS 上原生窗口验证（`scripts/native_smoke.py`）需要真实的桌面会话与可写的 `~/Library`；CI 或受限沙箱可能无法创建 WKWebView 数据目录，此时以打包后的 browser 模式冒烟为准。

需要检查 UI 时可启动独立预览服务，`--folder` 指向测试照片目录；它会打印访问地址，并将界面设置写入 `.qa/preview-ui-settings.json`：

```bash
python scripts/preview_ui.py --folder "$PWD/.qa/gallery"
```

`.qa` 目录被隔离使用；`HAVEN_DATA_DIR=.qa/data python main.py --browser` 可以把所有运行时数据放进仓库内。`scripts/verify_ui.cjs`、`verify_frosted_glass.cjs` 及其他 `verify_*.cjs` 使用 Playwright；先在 `.qa/` 安装 Playwright 和 Chromium。`verify_ui.cjs` 还要求 `.qa/gallery/` 中有命名为 `Photo-000.jpg` 至 `Photo-244.jpg` 的 245 张测试照片，以及可访问的服务 URL（`HAVEN_URL` 或 `.qa/server.log`）。这些脚本不属于发布程序的依赖。

`verify_frosted_glass.cjs` 检查毛玻璃相关的 DOM/CSS 断言（无 WebGL 画布、无自定义光标、`backdrop-filter`、透明度滑块持久化、深浅主题与 reduced motion），并把截图写入 `.qa/frosted-*.png`。

改动扫描、元数据或文件操作时运行后端测试；改动布局、毛玻璃效果、目录树、虚拟网格或查看器时，再用相应的浏览器脚本和原生窗口检查。浏览器预览不能代替 WebView2/WKWebView 的文件夹选择、原生拖放与窗口操作验证。

## 构建

### Windows

`build.spec` 将主程序打包为 `dist/Haven/` 的 one-folder 目录；`scripts/build.ps1` 另行构建 one-file 的 `updater.exe`，然后生成 `dist/Haven-win64.zip` 和 `dist/update.json`。ZIP 根目录直接包含 `Haven.exe`、`updater.exe`、`version.txt` 与 `_internal/`，不能再包一层目录。构建前关闭正在使用 `dist/Haven/` 的程序。

```powershell
venv\Scripts\python.exe -m unittest discover -s tests -v
powershell -ExecutionPolicy Bypass -File scripts\build.ps1
```

### macOS（arm64）

`build-mac.spec` 用 PyInstaller onedir + `BUNDLE` 生成 `dist/Haven.app`，Info.plist 含版本、bundle id、`LSMinimumSystemVersion=11.0`；`scripts/build_macos.sh` 负责构建、校验 arm64、`codesign --verify` 并用 `ditto` 生成保留符号链接的 `dist/Haven-mac-arm64.zip`。PyInstaller 默认 ad-hoc 签名；没有 Developer ID 时不做公证，用户首次打开需手动放行（见 README）。

```bash
.venv/bin/python -m unittest discover -s tests -v
PYTHON=.venv/bin/python ./scripts/build_macos.sh
```

图标 `logo.icns` 由 `docs/logo.png` 生成；需要更换时用 Pillow 生成 1024px PNG 后保存为 ICNS（或 `iconutil` 打包 iconset）。

### 更新流程

- `update.json` 顶层保留 Windows 的 `url/sha256/size`（老客户端兼容），`platforms` 里分别放 `windows-x64` 与 `macos-arm64`。客户端用 `updater.select_update()` 选择自己平台的条目，macOS 不会误装 Windows 包。
- macOS 更新：`updater_macos.install()` 下载 zip → `ditto -x` 解压 → 校验 Bundle ID、版本号、`codesign --verify` → 生成临时 shell 助手 → 应用退出；助手等待 PID 退出后备份旧 `.app`、复制新版本、去 quarantine 并重新打开，失败会恢复备份。下次成功启动时 `cleanup()` 删除旧版本备份和下载缓存。
- 运行位置检查：App Translocation（从下载目录/DMG 直接运行）、无写权限、磁盘空间不足都会在下载前拒绝并给出中文提示。
- 无 Developer ID 时不做公证；更新包由应用自身下载，不带 quarantine，替换后可直接启动，但 TCC 文件访问权限可能重新询问。

### 发布与 CI

`.github/workflows/release.yml` 在 tag `v*` 时并行运行 Windows 与 macOS 构建，再由 release job 汇总产物并生成 `dist/update.json`：

- `platforms.windows-x64`：Windows zip；顶层 `url/sha256/size` 同时保留，供已安装的 Windows 旧版本继续更新；
- `platforms.macos-arm64`：macOS zip（macOS 版暂未启用应用内更新）；
- 两个平台的版本号都来自同一个 `version.txt` / `config.VERSION`，构建时任一端失败都不会发布。

不要在 macOS 上构建 Windows 产物（或反过来）；需要验证 Windows 行为时使用 Windows CI 或真机。
